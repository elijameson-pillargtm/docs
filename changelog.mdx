## v3.7.0 -- April 19, 2026

**Named Guarantee Registry, 2,479 Test Suite, Integration Health Canary, Hermetic CI**

**The Guarantee now has structure.** Every behavior PILLAR commits to is a named, enforced, append-only invariant, and we can show you the exact test that proves each one. No more generic "we're well-tested" marketing claim — PILLAR's correctness is a falsifiable spec, not a promise.

- **The Guarantee: 63 Named Invariants Across 17 Categories** -- Each invariant has a stable ID (e.g. `G-F-02`, `G-T-05`, `G-I-11`), a plain-English statement, a pointer to the source file it protects, and a pointer to the test file that enforces it. Categories span scoring math (Freshness, Monotonicity, Bounds, Decomposition, Signals, Rules, Calibration), system boundaries (Tenancy, Validation), data fidelity (Ingestion, Forecast-weights, Org-config, Audit-shape), operational integrity (Hermeticity, Performance), and user-facing surfaces (UI, Endpoint contracts). Registry is append-only; retired invariants stay in the file with a pointer to their replacement.
- **Spec-Guarantee-Test Chain, Enforced at Build Time** -- 66 public SPEC entries (61 required + 5 aspirational roadmap). Every required spec entry must have at least one Guarantee enforcing it; every Guarantee must reference a real spec entry; every test `it(...)` description must start with the Guarantee ID it implements. A missing link anywhere in the chain fails the build. Browse the spec at https://github.com/pillargtm/pillar/tree/main/spec and the registry at https://github.com/pillargtm/pillar/blob/main/src/lib/scoring/__guarantees__/registry.ts.
- **2,479 Automated Tests with CI Gate** -- 2,376 unit tests + 103 integration tests + 3 Playwright UI tests, up from 2,395 in v3.5.0. Fixed-example tests for cases engineers hand-picked, property-based tests that throw thousands of random inputs at each invariant, endpoint-contract tests that lock API response shapes, Playwright tests for the auth entry point and public error paths. A failing Guarantee is a red build, no exceptions.
- **Integration Health Canary (G-I-10, G-I-11)** -- New `/api/cron/integration-health` runs every 15 minutes and catches the class of breakage unit tests can't see: a tenant's Salesforce OAuth token expires overnight, HubSpot rate-limits the nightly sync, the scoring cron stops firing for one tenant but not others, a connection flips to `disconnected` after a CRM-side revoke. A broken state MUST produce a CRITICAL-severity event that pages the on-call via Sentry → Slack; tokens nearing expiry (&lt;7d) produce WARNING-only events that track but don't page. Quiet tenants (zero active accounts) are skipped so they don't false-alarm.
- **Hermetic CI (G-H-01)** -- The integration-tests CI job no longer depends on any cloud Supabase credential. Runs against a local Supabase CLI stack started by the GitHub Action. Eliminates an entire class of paste-corruption failures where a rotated credential would silently break every PR check. Enforces the hermeticity invariant: CI must be runnable from a clean clone without access to production secrets.
- **Endpoint Contracts (G-E-01 through G-E-03)** -- Every scoring-model pure function behind `/api/scores/*` MUST return finite numbers in [0, 100] with a decomposition whose weighted_contributions sum to the final score ±1. Enforced across 300-500 random inputs per run via property-based testing (fast-check). Applied to `computeRenewalRisk`, `validationPassRate`, and the severity classification used by every score.
- **Input Validation at Every API Boundary (G-V-01, G-V-02)** -- Every `route.ts` that reads a JSON body or searchParams MUST run input through a Zod schema via `parseBody` / `parseQuery` from `@/lib/api-validation`, or be on a shrinking exemption allowlist. Partial conversion (both validated and raw parsing in the same file) is forbidden. Shrinks the surface for malformed-input crashes across 92 route files.
- **Tenancy Audit: Downstream Helpers + POST Handlers (G-T-05, G-T-06)** -- The existing per-route tenancy walk caught top-level handlers but missed two classes of leak: workflow helpers invoked by routes (`handleTaskCompletion`, `handleStartWorkflow`) that accepted an account_id from request state without re-filtering by org_id, and POST handlers where the body supplied customer-controlled IDs. Both classes now require explicit `.eq('org_id', orgId)` on every org-scoped query. 11 task-helper gaps and 4 plays POST gaps closed; both patched classes are now locked at the invariant level.
- **Ingestion Fidelity: Support, Contracts, Usage, Adoption (G-I-06 through G-I-09)** -- Four new Ingestion invariants lock the field-mapping + override fidelity for four connector paths. `G-I-06`: HubSpot Service Hub and Salesforce Service Cloud support-ticket snapshots feed `computeSupportBurden` → `renewal_risk` with a well-defined fallback chain. `G-I-07`: when a non-terminated contracts row exists, the renewal anchor uses `contracts.end_date`, falling back to `renewals.renewal_date` for tenants without contracts enumerated yet. `G-I-08`: Pendo/Mixpanel/Amplitude/Segment/Heap usage snapshots feed `computeUsageTrend` → `renewal_risk`, with a NEUTRAL baseline (trend_score=50) on insufficient data so missing usage data never downgrades an account. `G-I-09`: `applyAdoptionPctOverwrite` overwrites `account_products.adoption_pct` from snapshot-derived utilization, preserving the legacy CRM value as `adoption_pct_legacy_crm` and injecting a synthetic row if the products array is empty so aggregation rules (e.g. RR-USAGE-001) still have something to average.
- **Score Decomposition Row Contract (G-A-01 through G-A-03)** -- Every `scoring_audit` row persisted by the pipeline MUST populate `decomposition`, `input_values`, and `weights_used` on every account-grain and opportunity-grain score. Fixes a prior state where 96k+ rows had empty decomposition in production, breaking the UI that reads them. Additionally, `nps_score` and `champion_active` are now synced on every invocation from the renewals and contacts source-of-truth tables, not from the potentially-stale cached copies on the account row.
- **UI Guarantees via Playwright (G-U-01 through G-U-03)** -- First Playwright-backed Guarantees, enforced against the live dev server in CI: the `/login` page responds non-5xx and renders an interactive email input; `/api/architects/unsubscribe?t=<invalid>` returns a branded 200 HTML page rather than a 500 with a stack trace. Data-aware UI invariants (account detail scoring, triage ordering, signal feed tenancy) are tracked as aspirational `SPEC-UI-04`..`SPEC-UI-06` and land with the hermetic Playwright fixture seed.
- **Property-Based Coverage of Existing Invariants (G-B-02, G-M-03)** -- A fixed-example test proves an invariant for the inputs the author thought to write; a property-based test proves it across the input space. `G-B-02` reinforces the bounds invariant via 500 random inputs per run; `G-M-03` reinforces the `computeRenewalUrgencyFactor` monotonicity invariant via 1000 random inputs.
- **Performance Invariants (G-P-01, G-P-02)** -- `computeAllScoresForAccount` MUST score 1,000 synthetic accounts in under 10 seconds wall clock, with steady-state per-call p95 ≤ 15ms and p99 ≤ 50ms (post-warmup), and no single call exceeding 500ms. Additionally, the per-account cost at N=1,000 must be within 2.5× of the per-account cost at N=100, so a super-linear regression fails the build before it can starve the cron.

## v3.6.0 -- April 16, 2026

**65-Tool MCP Surface, Drafter Agent, Shared Tool Catalog, Accounts API Fix**

- **MCP Server: 65 Tools Across 6 Tiers** -- Expanded from 26 tools to 65 covering every layer of the revenue architecture. Full catalog now spans core intelligence, plays intelligence, tasks & activities, expansion whitespace, financial cascade (NRR impact simulation, procurement calendar, cohort curves, forecasted renewals, customer readiness), market intelligence (TAM/SAM, territory equity, headcount simulation, K-12 district intelligence, data health), AI orchestration (Ask PILLAR RAG, narratives, generated action plans, account intelligence, coaching insights, board narratives), scoring transparency (backtest, scoring profile, forecast weights, contracts config, scoring thresholds), and governed writes (create/update task, update signal status, set renewal disposition, opt-in benchmarks).
- **Drafter Agent (Global)** -- The in-app agentic layer (renamed from "Copilot" due to Microsoft brand conflict) is now mounted globally across every authenticated page via a compact floating chat widget. Ask any GTM question and Drafter routes to the right subset of MCP tools automatically. Every run writes to the `agent_actions` audit table for the approval gate + flywheel learning.
- **Shared Tool Catalog (Single Source of Truth)** -- All tool definitions now live in `src/lib/mcp/tool-catalog.ts`. Both the external MCP server and the in-app Drafter runtime consume from this catalog. Prevents the class of drift that caused a silent 404 on `search_accounts` when each consumer maintained its own parallel tool list.
- **`/api/accounts` GET Route** -- New lean-list endpoint supporting `?search=` (fuzzy name match), plus explicit `?segment=`, `?tier=`, `?territory=`, `?limit=` filters. Returns the full scoring row per account ordered by priority. Fixes `search_accounts` for both the external MCP server and the in-app Drafter.
- **Temporal Context in Drafter** -- Every Drafter run now prepends today's date + day-of-week (America/New_York) to the system prompt so urgency phrasing anchors to the user's actual now, not the model's training cutoff. No more "Monday briefing" on a Wednesday.
- **Drafter UI: Ask-PILLAR-style Chat Widget** -- Compact 380px floating chat panel matching the marketing site's Ask PILLAR aesthetic. User/bot message bubbles, auto-growing textarea, inline proposal cards with approve/reject/skip controls, evidence-trail disclosure. Dark-slate pill FAB in the bottom-right of every authenticated page.
- **Org-Agnostic Example Prompts** -- Drafter welcome message uses `[account name]` placeholder convention so pilot users at any org see examples that work with their own data rather than hardcoded references.

## v3.5.0 -- April 12, 2026

**Per-Organization Configuration, Fiscal Year Engine, Segment Intelligence**

- **2,395 Automated Tests with CI Gate** -- Test suite expanded from 1,874 to 2,395 tests across 52 files. New coverage spans fiscal year computation, segment classification, deal stage probability resolution, signal threshold overrides, org config null-safety, and currency formatting.
- **Fiscal Year Engine** -- Every metric that involves a time period (pipeline coverage, quota attainment, budget variance) now computes against the organization's fiscal year rather than the calendar year. Configure your fiscal year start month in **Settings → Configuration → Business Definitions**. Organizations that start their fiscal year in any month from January through December are fully supported.
- **Per-Org Segment Thresholds** -- SMB, Mid-Market, and Enterprise classification boundaries are now configurable per organization. Default boundaries (SMB ≤ $50K ARR, Mid-Market ≤ $500K ARR) are used until overridden. Configure in **Settings → Configuration → Segments & Thresholds**.
- **Per-Org Deal Stage Probabilities** -- Close probability by deal stage is now configurable per organization. PILLAR ships with 30+ default stage mappings tuned for EdTech sales cycles. Override any stage's probability in **Settings → Configuration → Deal Stages**. Unrecognized stages fall back to 15%.
- **Per-Org Signal Thresholds** -- Eight signal-triggering thresholds (health warning/critical, renewal risk, ICP fit, engagement velocity, pipeline coverage, win rate, CAC ratio) are now overridable per organization. Configure in **Settings → Configuration → Segments & Thresholds**.
- **ARR Definition** -- Organizations can choose how ARR is measured: Contracted ACV (default), Trailing 12-Month Revenue, or MRR × 12. Configure in **Settings → Configuration → Business Definitions**.
- **Churn Definition** -- Three churn definitions supported: Revenue Churn (default), Logo Churn, and Net Revenue Retention-based. Configure in **Settings → Configuration → Business Definitions**.
- **Base Currency** -- Reports, deck exports, and financial calculations now use the organization's configured base currency. Ten currencies supported (USD, EUR, GBP, CAD, AUD, JPY, SGD, CHF, SEK, DKK). Configure in **Settings → Configuration → Business Definitions**.
- **Renewal Window** -- The look-ahead window for renewal risk monitoring is configurable from 14 to 730 days (default: 90). Configure in **Settings → Configuration → Business Definitions**.
- **Quota Type** -- Five quota structures supported: ARR, TCV, Revenue, Activity, and Blended. Affects quota attainment calculations across the platform. Configure in **Settings → Configuration → Business Definitions**.
- **Expansion Taxonomy** -- Organizations can define custom expansion categories (upsell, cross-sell, add-on seats, etc.) with their own labels. Used in the Expansion Pipeline and product affinity reporting. Configure in **Settings → Configuration → Deal Stages**.
- **Contact Role Patterns** -- Executive buyer and champion identification is now driven by configurable title-matching patterns. PILLAR ships with sensible defaults (VP, CTO, Chief, Director for execs; Champion, Advocate, Power User for champions). Configure in **Settings → Configuration → Deal Stages**.
- **DB Migration: 11 New Org Config Columns** -- All per-org configuration is stored directly on the `organizations` table. NULL = use PILLAR global default, so existing organizations continue working without any migration required.
- **Settings UI: Configuration Tab** -- All per-org configuration consolidated into a single **Settings → Configuration** tab with four sub-sections: Business Definitions, Segments & Thresholds, Deal Stages, and Pipeline Weights. Role-gated to CRO/CEO, RevOps, and Pillar Admin.
- **The Guarantee: 8 New Invariants (G-O-01 through G-O-08)** -- Formally registered correctness guarantees for the per-org config layer: fiscal period computation, stage probability resolution, segment classification, signal threshold precedence, null-safety, currency formatting, enum validation, and contact role pattern classification.

## v3.4.0 -- April 4, 2026

**Mathematical Integrity Architecture, Data Readiness Gate, Formula Audit**

- **1,874 Automated Tests with CI Gate** -- Every deployment to production must pass the full test suite before Vercel allows the build to complete. Zero chance of deploying broken math. (Test count grew to 2,395 in v3.5.0.)
- **Formula Correctness Audit** -- Audited 45+ formulas against industry standards. Fixed 5 material errors: win rate denominator (bowtie), LTV/CAC missing gross margin (scoring), CAC payback missing gross margin (dashboard), NRR conflation with total growth (decision-engine), Rule of 40 linear vs compounding annualization (org-metrics). Resolved 3 cross-file inconsistencies in burn multiple, magic number, and forecast commit weights.
- **Data Readiness Gate** -- New enforcement layer that checks CRM data quality before scoring runs. Three states: ready (85%+), degraded (60-84%), blocked (<60% or critical issues). Banner displays on all authenticated pages when data quality is insufficient.
- **Record-Level Data Quality Drill-Down** -- New `/api/data-readiness/affected-records` endpoint identifies every specific account with data issues, what's wrong, and severity. No more "150 accounts have problems" without knowing which 150.
- **Stale Contact Signal Cascade** -- Detects contacts with no engagement for 4+ months (120 days). Generates cascading signals: stale contact data, no active champion, no active executive buyer, no active stakeholder (CRITICAL). A contact that exists but hasn't engaged is functionally no contact.
- **Scoring-to-Source Consistency Tests** -- New test class that verifies scoring audit decomposition matches actual contact, renewal, and activity data. Catches the class of bug where displayed scores don't reflect reality.
- **Seed Data Integrity Fix** -- `seed-scores.ts` now queries actual contacts, renewals, and activities to derive scoring inputs instead of generating random values. Account 360 score decomposition now reflects real data.
- **Cross-Endpoint Consistency: Full Coverage** -- Expanded from 11 to 32 cross-endpoint tests covering all endpoint pairs that display overlapping metrics (expansion, territory economics, decision engine, TAM/SAM, budget variance, NRR impact, leads, plays, all scoring models).
- **Module Tier Gating** -- 18 pages enforce module-based access control. Shows "Module Not Activated" UI instead of silent redirect when a module isn't unlocked.
- **MCP Server: 22 Tools** -- Added `get_data_readiness` and `get_affected_records` tools for AI-assisted data quality monitoring.

## v3.3.0 -- April 4, 2026

**Renewal Forecasting, Procurement Intelligence, Product Affinity, Cohort Intelligence, Playbook Evolution, Board Narratives**

- **Renewal Forecasting Engine** -- Per-renewal probability model with risk factor and positive signal decomposition. Computes org-level GRR/NRR projections weighted by ARR. Inputs include health score, risk score, engagement, disposition, days to renewal, active playbooks, critical signals, NPS, contract tenure, and deal size.
- **Procurement Intelligence** -- Maps each account's fiscal year into a complete procurement calendar with budget planning, approval, and allocation windows. Assesses renewal-to-budget alignment, generates milestone-based engagement timelines, forecasts budget cycle status per quarter, and identifies procurement risks including misalignment, late engagement, budget freeze, election cycle, and complex procurement.
- **Product Affinity Matrix** -- Computes co-adoption rates, cross-sell timelines, and ARR uplift for every product pair, both overall and per segment. Generates prioritized expansion signals scored by multiple weighted components. Four-state signal lifecycle (pending/pitched/won/dismissed). Extends the Expansion Pipeline with product-pair intelligence.
- **Cohort Intelligence** -- Auto-generates cohorts by vintage quarter, segment, territory, and rep. Computes per-cohort NRR, GRR, churn, expansion, and contraction. Generates 36-month vintage retention curves. Detects anomalies including low NRR, accelerating churn, and health score decline.
- **Playbook Evolution** -- Closed-loop play effectiveness tracking. Groups completed plays by template, segment, and tier, then computes win rates, average time to completion, ARR impact, and health delta. Generates play recommendations using segment affinity scoring and signal severity. Flags underperforming templates.
- **Board Narrative Generation** -- AI-powered board-ready narratives using Claude. Five narrative types (executive summary, QBR, renewal forecast, territory health, pipeline update) with three tone options (board formal, exec concise, detailed analytical). Pre-computed KPI injection ensures generated numbers match verified PILLAR data. Full data snapshot saved for auditability.
